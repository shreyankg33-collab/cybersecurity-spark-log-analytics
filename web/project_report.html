Cybersecurity Data Analytics: Log Analysis with Scala & Spark

Topic: Analyzing Web-Server Access Logs to Identify Security Incidents & Threat Vectors
Core Technologies: Apache Spark 3.5.0 (Core & SQL), Scala 2.12.18, SBT, Dynamic Sliding Windows

1. Executive Summary & Problem Statement

Modern web infrastructure produces millions of unstructured HTTP access log lines every hour. Traditional manual inspection or single-threaded scripts (e.g. Pandas) cannot scale across gigabytes/terabytes of data or detect stateful, multi-stage attacks across time. This project implements a distributed Big Data cybersecurity pipeline using Apache Spark and Scala. The system parses access logs, executes parallel signature matching and sliding-window behavioral anomaly detection, computes multi-factor IP threat scores, and exports alerts to enterprise SIEM platforms.

6. Evaluator Viva Q&A Defense

Evaluator QuestionYour Winning Answer
Why Spark and Scala instead of Python/Pandas? Pandas is single-threaded and limited to a single machine's RAM. Spark partitions data across CPU cores and clusters. Scala runs directly on the JVM with zero serialization overhead and provides compile-time type safety.
How do you track attacker IPs over time? We use Spark SQL Window functions: Window.partitionBy($"clientIp").rangeBetween(-60, 0). This groups requests chronologically by IP within a 60-second sliding window to detect rapid auth failures or request spikes.
Is this project dynamic or hardcoded? It is 100% dynamic. You can feed it any web server access log from any company, and Spark calculates the rolling windows, regex matches, and mathematical risk scores on-the-fly.
How is this deployed in production? We containerized the application with Docker (Dockerfile and docker-compose.yml) and configured sbt assembly to produce a Fat JAR deployable to Kubernetes or YARN clusters via spark-submit.
